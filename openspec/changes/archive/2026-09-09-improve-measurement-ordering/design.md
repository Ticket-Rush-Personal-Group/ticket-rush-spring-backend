## Context

第 11 支取得了八組數據,但留下一個**實驗設計上的缺陷**:

八組是「平台四組跑完,再跑虛擬四組」。而四組虛擬的全距是 20.6%～53.1%,四組平台是 6.0%～8.9%。

**問題不在於哪個數字對,而在於這兩件事完全分不開:**

- 虛擬執行緒本身的吞吐比較不穩定?
- 還是虛擬那四組剛好都排在後半段,而主機狀態隨時間漂移?

第 11 支已經實測到主機狀態確實會漂移(同一設定在不同時間點量到 1800 與 4964),
所以第二種解釋不是空想。**在分開之前,「虛擬執行緒的變異較大」這句話不能說。**

這是實驗設計的問題,不是量測精度的問題 —— **加再多輪暖機也解不掉**,
因為每一組的暖機都很完整,問題出在八組之間的時間分佈。

## Goals / Non-Goals

**Goals:**

- 讓「執行緒模型」與「時間順序」可以分開 —— 交錯量測
- 讓「環境在這段時間內漂移了多少」成為**批次自帶的、可證偽的數字**,而不是事後的猜測
- 產出一個可重跑的編排腳本 —— 成功標準要求「每個數字都有可重跑的 k6 腳本支撐」,
  而目前八組是靠我手動下了二十幾道指令湊出來的

**Non-Goals:**

- **不改動任何量測參數** —— 請求數、庫存、暖機協定、每組每輪的量測次數全部維持不變。
  **本支唯一改變的是順序。** 一次只動一個變數
- **不改動任何應用程式碼**
- **不預設虛擬執行緒應該贏或輸** —— 見 D5

## Decisions

### D1. 交錯的單位是「一輪跑完全部八組」,不是「同一組連續跑三次」

原本:`for 每一組 { 重啟; 暖機; 量三次 }`
改為:`for 每一輪 { for 每一組 { 重啟; 暖機; 量一次 } }`,共三輪。

每一組仍然得到三個量測值,但那三個值**分散在整段時間裡**。時間漂移因此對八組的影響變成**共同的雜訊**,而不是偏向某幾組的**偏差**。

**代價很直接:重啟從 8 次變成 24 次。** 每次重啟都含「暖到收斂」,因為暖度是綁在 JVM 實例上的,重啟就沒了 —— 這一項無法省。預估總時長約 45 分鐘。

**那是這個缺陷的實際價格。** 不付的話,八組表格裡有一半的比較是不能用的。

### D2. 每一輪輪換組別順序,消除位置偏差

只做 D1 還不夠:若每一輪的順序都相同,某一組就永遠在「剛開始」、另一組永遠在「最後」。

因此每一輪把順序旋轉:

```
第 1 輪: 1 2 3 4 5 6 7 8
第 2 輪: 4 5 6 7 8 1 2 3
第 3 輪: 7 8 1 2 3 4 5 6
```

每一組在三輪裡落在三個不同的位置。

**不選「隨機打亂」**:只有三輪的情況下,隨機無法保證位置分佈平均 —— 完全可能三輪都把某組排在最後。**旋轉是確定性的,而且在這個規模下比隨機更均衡。**

### D3. 漂移指標由批次自己產生,而且要能否決整批數據

**每一輪的整體水位**(該輪八組吞吐的中位數)就是那一輪的環境指標。三輪的水位差距即為這段時間的漂移。

判準:**若三輪水位的全距超過 15%,整批數據作廢** —— 那代表環境在量測期間的變化大到足以蓋過層與層之間的差異,交錯也救不回來。

**這個做法不花額外的時間** —— 水位是從已經要量的八組算出來的,不需要額外的哨兵組。

**不選「另外跑一個固定的哨兵組」**:那要多付三次重啟加暖機(約六分鐘),
而它提供的資訊與「整體水位」高度重疊。

**為什麼要有一個能否決整批的判準:** 沒有它的話,「環境漂移」永遠可以在事後被拿來解釋任何不利的數字 —— 那不是解釋,是藉口。**先訂好門檻,才有資格說「這批不算」。**

### D4. 每次量測記錄時間戳

每一次量測都記下它在整個批次中的相對時刻。這讓「某組的三個值是否隨時間單調變化」可以事後檢查 —— 而第 11 支的教訓正是**單調的變化不是雜訊**。

### D5. 三種結果都算成功

事先寫下來,避免結果出來之後才決定什麼算成功:

| 結果 | 意義 |
| --- | --- |
| 虛擬組的全距降到與平台組相當 | **先前的高變異是時間順序造成的** —— 第 11 支的觀察被推翻 |
| 虛擬組的全距仍然明顯較高 | **那是執行緒模型本身的性質** —— 此時才有資格這樣說 |
| 三輪水位全距 > 15%,整批作廢 | **環境無法支撐這個比較** —— 這也是結論,而且它會指出下一步該做什麼 |

**目的是讓那個問題變得可回答,不是讓虛擬執行緒贏。**

### D6. 編排寫成可重跑的腳本,不留在對話裡

第 11 支的八組是我手動下二十幾道指令湊出來的 —— 而成功標準寫的是「每個數字都有**可重跑的**腳本支撐」。

因此新增 `k6/run-comparison-matrix.sh`:一道指令跑完整個矩陣並輸出表格。
**它同時是 Phase 1 交付物的一部分** —— README 裡的每個數字都要能指向它。

## Risks / Trade-offs

- **[總時長約 45 分鐘]** → D1 的直接代價,無法迴避。**不付就等於接受一半的比較不可用**
- **[三輪仍然偏少]** → 三個量測值只能看出粗略的趨勢。但四輪要一小時,
  而本支的目的是**分離混淆**,不是把誤差壓到最小 —— 交錯本身就已經把偏差變成雜訊
- **[整批可能作廢]** → 那是 D3 刻意保留的可能性。**一個永遠不會失敗的驗收不是驗收**
- **[旋轉順序仍非完全平衡]** → 八組三輪不可能完全平衡。旋轉保證每組落在三個不同位置,
  這在此規模下已足夠

## Migration Plan

**不改動應用程式碼,無 schema 變更,無相依變更。**

`k6/run-load-test.sh` 的既有行為完全不變 —— 新增的編排腳本呼叫它,不修改它的預設值。
